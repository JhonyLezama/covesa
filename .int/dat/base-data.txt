INSTRUCCIONES PARA EL AGENTE DE IA
---------------------------------------------------------------------
Tu tarea es generar, en este orden exacto, los siguientes artefactos
de Laravel para el proyecto COVESA:

1. Migraciones (php artisan make:migration) — respetar el ORDEN DE
   CREACIÓN indicado en la sección "ORDEN DE MIGRACIONES", ya que hay
   dependencias de llaves foráneas.
2. Modelos Eloquent con sus relaciones (belongsTo, hasMany, morphMany,
   etc.) según se detalla en cada tabla.
3. Seeders con datos de prueba realistas (ver sección "DATOS SEMILLA").
4. Ejecutar `php artisan migrate:fresh --seed` y confirmar que corre
   sin errores.

Reglas generales de implementación:
- Usar `SoftDeletes` en: properties, projects, blog_posts, leads.
- Usar el paquete `spatie/laravel-permission` para roles y permisos
  de usuarios (NO crear una tabla `roles` propia).
- Usar relaciones polimórficas de Laravel (`morphMany`) para la tabla
  `media` (mediable_id, mediable_type).
- Todas las tablas de catálogo (`property_types`, `zones`, `statuses`)
  deben tener `is_active` y `order` para poder administrarlas desde
  el CMS sin necesidad de eliminarlas físicamente.
- Las tablas de traducción (`*_translations`) llevan índice único
  compuesto sobre (padre_id, locale) para evitar duplicados de idioma.
- No crear columnas nuevas para cada campo variable de formularios;
  usar el campo JSON `extra_data` en `leads` para eso (ver detalle).

DETALLE DE TABLAS
=====================================================================

-----------------------------
1. property_types  (catálogo)
-----------------------------
Propósito: tipos de propiedad (Terreno Comercial, Terreno Industrial,
Local Comercial, Local Industrial, Terreno Rústico, etc.)

Campos:
- id                bigint PK
- name              string
- slug              string, unique
- icon              string, nullable      (nombre de ícono lucide-react)
- description       text, nullable
- is_active         boolean, default true
- order             unsignedInteger, default 0
- timestamps

-----------------------------
2. zones  (catálogo, jerárquico)
-----------------------------
Propósito: ubicaciones (Trujillo, Piura, Sullana, sectores específicos).
Soporta jerarquía Región > Provincia > Sector vía parent_id.

Campos:
- id                bigint PK
- name              string
- slug              string, unique
- parent_id         bigint FK -> zones.id, nullable, onDelete: null
- department        string, nullable   (redundancia intencional para
                                         filtros rápidos sin recorrer
                                         el árbol de jerarquía)
- latitude          decimal(10,7), nullable
- longitude         decimal(10,7), nullable
- is_active         boolean, default true
- order             unsignedInteger, default 0
- timestamps

-----------------------------
3. statuses  (catálogo genérico de estados)
-----------------------------
Propósito: tabla ÚNICA para todos los estados del sistema, diferenciados
por columna `type`. Evita duplicar tablas idénticas (property_statuses,
project_statuses, lead_statuses, referral_statuses).

Valores de `type` usados actualmente: "property", "project", "lead",
"referral". El agente debe dejar el diseño abierto a nuevos `type` sin
requerir cambios de esquema.

Campos:
- id                bigint PK
- type              string   ("property" | "project" | "lead" | "referral")
- name              string   (ej: "En venta", "En construcción", "Nuevo")
- slug              string
- color             string, default '#0C447C'   (hex, para pintar badges)
- order             unsignedInteger, default 0
- is_active         boolean, default true
- timestamps
- UNIQUE(type, slug)

-----------------------------
4. users  (ampliación de la tabla base de Laravel)
-----------------------------
Agregar a la migración por defecto de Laravel los siguientes campos:
- phone             string, nullable
- photo             string, nullable   (foto de perfil, se muestra en
                                         fichas de propiedad como asesor)
- position          string, nullable   (ej: "Broker corporativo")
- is_active         boolean, default true
- softDeletes

Roles a crear vía spatie/laravel-permission (seeder, NO migración):
- admin      -> acceso total al CMS
- editor     -> administra contenido, no usuarios ni configuración
- comercial  -> solo ve/gestiona leads y referidos asignados a él

-----------------------------
5. projects
-----------------------------
Propósito: proyectos grandes con landing propia (El Milagro, Hanan del
Sol, y futuros). El contenido traducible NO va aquí, va en
project_translations.

Campos:
- id                bigint PK
- name              string   (nombre interno/administrativo)
- slug              string, unique   (usado en URL /proyectos/{slug})
- status_id         FK -> statuses.id
- zone_id           FK -> zones.id
- client_name       string, nullable   (empresa cliente del proyecto,
                                         ej: "Aspromermet")
- service_type      string, nullable   (ej: "Project Management",
                                         "Gestión de Activos")
- featured_image    string, nullable
- gallery           json, nullable
- video_url         string, nullable
- latitude          decimal(10,7), nullable
- longitude         decimal(10,7), nullable
- is_published      boolean, default false
- order             unsignedInteger, default 0
- timestamps
- softDeletes

Relaciones Eloquent:
- belongsTo(Status::class)
- belongsTo(Zone::class)
- hasMany(ProjectTranslation::class)
- hasMany(Property::class)
- hasMany(Lead::class)
- morphMany(Media::class, 'mediable')

-----------------------------
6. project_translations
-----------------------------
Campos:
- id                    bigint PK
- project_id            FK -> projects.id, cascadeOnDelete
- locale                string(2)   ("es" | "en" | "fr")
- title                 string
- subtitle              string, nullable
- description           text
- features              json, nullable   (array de características,
                                           ej: ["Club House Exclusivo",
                                           "Seguridad para tu familia"])
- meta_title            string, nullable
- meta_description      text, nullable
- timestamps
- UNIQUE(project_id, locale)

-----------------------------
7. properties
-----------------------------
Propósito: propiedades individuales (terrenos, locales). Pueden
pertenecer a un proyecto o ser independientes.

Campos:
- id                    bigint PK
- project_id            FK -> projects.id, nullable
- property_type_id      FK -> property_types.id
- zone_id               FK -> zones.id
- status_id             FK -> statuses.id
- assigned_user_id      FK -> users.id, nullable  (asesor asignado)
- title                 string   (nombre propio, ej: "Carretera
                                   Huanchaco" — NO se traduce)
- slug                  string, unique
- operation             enum('venta','alquiler')
- area_total            decimal(12,2)
- area_unit             string, default 'm2'
- price                 decimal(12,2), nullable  (nullable: algunas
                                                    fichas dicen "Consultar")
- currency              string, default 'USD'
- price_type            enum('total','por_m2')
- lots_available        integer, nullable  (ej: "4 Lotes")
- ideal_for             json, nullable  (array de tags, ej:
                                          ["Almacenes","Depósitos"])
- featured_image        string
- gallery               json, nullable
- latitude              decimal(10,7), nullable
- longitude             decimal(10,7), nullable
- address               string, nullable
- is_published          boolean, default false
- is_featured           boolean, default false
- views_count           integer, default 0
- timestamps
- softDeletes

Relaciones Eloquent:
- belongsTo(Project::class)
- belongsTo(PropertyType::class)
- belongsTo(Zone::class)
- belongsTo(Status::class)
- belongsTo(User::class, 'assigned_user_id')
- hasMany(PropertyTranslation::class)
- hasMany(Lead::class)
- hasMany(Referral::class)
- morphMany(Media::class, 'mediable')

NOTA DE NEGOCIO PENDIENTE (dejar comentario en el código):
Confirmar con el cliente si TODAS las propiedades requieren traducción
completa (mayor carga operativa al subir cada propiedad) o solo el
contenido institucional/proyectos grandes se traduce, dejando las
fichas de propiedades individuales solo en español. Mientras no se
confirme, implementar property_translations igual, pero dejar el
campo opcional en el formulario del CMS.

11. leads  (mini-CRM propio — TODOS los formularios del sitio)
-----------------------------
Campos:
- id                        bigint PK
- source                    string  ("contacto" | "vende_tu_propiedad" |
                                      "landing_proyecto" |
                                      "busca_propiedad" | "refiere_y_gana")
- property_id               FK -> properties.id, nullable
- project_id                FK -> projects.id, nullable
- referral_id               FK -> referrals.id, nullable
- assigned_user_id          FK -> users.id, nullable
- status_id                 FK -> statuses.id, nullable
- first_name                string
- last_name                 string, nullable
- document_type             string, nullable  (DNI, RUC, CE)
- document_number           string, nullable
- email                     string
- phone                     string
- location                  string, nullable
- message                   text, nullable
- extra_data                json, nullable  (VER DETALLE ABAJO)
- attachments               json, nullable  (array de rutas de archivos)
- accepted_data_policy      boolean, default false
- accepted_marketing_policy boolean, default false
- notes                     text, nullable  (notas internas del asesor)
- timestamps
- softDeletes

DETALLE de extra_data (json) — campos variables según el formulario de
origen, NO crear columnas separadas para esto:
  - Formulario "vende_tu_propiedad": direccion_terreno, zonificacion,
    precio_venta
  - Formulario landing "El Milagro": tipo_puesto, rubro
  - Formulario landing "Hanan del Sol": metraje_deseado, rubro

Relaciones Eloquent:
- belongsTo(Property::class)
- belongsTo(Project::class)
- belongsTo(Referral::class)
- belongsTo(User::class, 'assigned_user_id')
- belongsTo(Status::class)

-----------------------------
12. referrals  (Refiere y Gana)
-----------------------------
Campos:
- id                        bigint PK
- referrer_user_id          FK -> users.id, nullable
- referrer_name             string
- referrer_email            string
- referrer_phone            string
- referred_name             string
- referred_email            string, nullable
- referred_phone            string
- code                      string, unique  (para tracking de link,
                                              ej: ?ref=ABC123)
- status_id                 FK -> statuses.id
- property_id               FK -> properties.id, nullable
- sale_amount               decimal(12,2), nullable
- commission_percentage     decimal(5,2), default 0
- commission_amount         decimal(12,2), nullable  (calculado:
                                sale_amount * commission_percentage / 100)
- commission_paid_at        timestamp, nullable
- timestamps
- softDeletes

Relaciones Eloquent:
- belongsTo(User::class, 'referrer_user_id')
- belongsTo(Property::class)
- belongsTo(Status::class)
- hasMany(Lead::class)

NOTA DE NEGOCIO PENDIENTE: confirmar con el cliente si
commission_percentage es fijo para todos los referidos o varía según
tipo de propiedad/monto. Si varía de forma compleja, evaluar una tabla
"commission_rules" en una fase posterior. Por ahora es un campo simple
editable manualmente por un admin al cerrar la venta.

14. settings  (configuración global, patrón key-value)

                                       "linkedin_url")
- value              text, nullable
- type               string, default 'text'  ("text"|"image"|"json")
- group              string, nullable  ("contact"|"social"|"seo")
- timestamps
